Symlink System

Claude Code discovers skills only in ~/.claude/skills/ and project .claude/skills/. Team vault is a subfolder — not auto-discovered. Symlinks bridge the gap.

Talk Blocks

Structured presentation blocks for today's team stack demo. Each block = one presentation segment.

1 Stack Architecture

  • 3 access levels: Global (personal) → Team (shared vault) → Local (project)
  • Skills = Markdown files, not code. Anyone on the team can edit via Obsidian
  • Symlinks bridge Obsidian vault to Claude Code skill discovery
  • sync-team-skills.sh — one command to connect new team skills
Key message: composable layer cake. Each level overrides the previous. Team edits propagate automatically via Obsidian Sync — no deployment, no CI, just Markdown.

2 Bot Infrastructure

  • Pulse bot (@randotndtes_bot) — automated 2h summaries from 7 chats → AIM agi
  • Claude bot (@AIM_claude_bot) — interactive agent, full Claude Code via Telegram DM
  • Allowlist access control — only approved team members
  • Both bots can trigger any team skill + access all MCP servers
Key message: bots extend the stack beyond the terminal. Team gets AI capabilities in familiar Telegram. Pulse = ambient awareness. Claude bot = direct skill library access.

3 CTRL Dashboard — Live Demo

  • Single-file terminal-aesthetic dashboard, FastAPI backend (3500+ lines)
  • VOX AI advisor — context-aware day planning (calendar + Linear + vault)
  • Telegram bridge — reads 7 team chats in real-time
  • Linear integration — ambient task awareness in footer
Key message: command center. Everything connects here. Built iteratively with Claude Code, single-file philosophy. Show: VOX query, task panel, Telegram bridge.

4 Pipelines in Action

  • Content: idea → voice → visual → UTM → publish (5 skills chained)
  • Lab sprint: full lifecycle setup → announce → monitor → sync → close
  • Meeting: Krisp → summary → Telegram → Linear (fully automated)
  • Presentation: brief → deck-ainative → style → dashboard → present
Key message: skills are not isolated — they chain into pipelines. Each pipeline covers a complete workflow. Yesterday's dashboard + presentation = end-to-end example.

5 What the Team Gets

  • 17 AIM-* team skills in shared vault — editable by anyone
  • 8 MCP server connections (Linear, Notion, Telegram, Calendar, Krisp, Sheets, Exa, Playwright)
  • Pulse bot: ambient awareness every 2 hours in AIM agi
  • Claude bot: direct AI access via Telegram (allowlisted)
  • CTRL dashboard (Alex-only now, team access planned)
Key message: not a personal toolbox. 17 skills shared, bots serve the whole team, MCP connections pull from team-wide sources. Every new skill automatically becomes available to everyone through Obsidian Sync.

6 Q&A / Speaker Notes

  • “How do team members edit skills?” — Open Obsidian, edit Markdown in aim-rules/skills/
  • “Can the bot access everything?” — Allowlist controls + restricted channel list
  • “How does the dashboard connect to Linear?” — MCP server + ambient footer
  • “Can others run Claude Code?” — Dan (tech) can, others via Telegram bot
  • “Security?” — Allowlists, restricted channels, local-only dashboard, no public endpoints
